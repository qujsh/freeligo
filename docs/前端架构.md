# 前端架构

> 2026-10-25 接入更新：公开分类、首页分页筛选、大厅、任务预览和详情已接真实后端；实现见 `src/services/publicTasks.ts`，默认 api 模式，可显式切换 mock。下文关于本机数据、写操作和演示会话的描述适用于 mock 模式；收藏、意向、发布、选人仍未接入真实接口。

## 当前目录职责

| 目录 | 职责 |
| --- | --- |
| `src/app` | 应用壳、路由、全局入口与弹层 |
| `src/modules/discovery` | 首页、机会大厅、筛选与展示 |
| `src/modules/tasks` | 项目 / 任务详情、快速预览、意向表单 |
| `src/modules/publishing` | 发布流程、草稿与预览 |
| `src/modules/publisher` | 发布者工作台和申请处理 |
| `src/modules/account` | 演示会话与占位页面 |
| `src/domain` | 业务类型与平台无关规则 |
| `src/services/contracts` | 页面使用的业务服务契约 |
| `src/services/mock`、`src/mocks` | 模拟实现与种子数据 |
| `src/services/index.ts` | 服务实现装配入口 |
| `src/shared/ui` | 可复用展示组件 |
| `src/styles` | 基础样式、品牌及参考图样式 |

依赖方向：页面 / 业务组件 → 查询或业务服务 → 契约与 domain；服务实现不依赖 Vue 页面；shared 不反向引用 modules。Pinia 会话供页面和操作流程使用。

目前跨模块复用包含 account/session 和 tasks/PreviewDrawer 等直接引用。后续出现更多消费者时建立明确的模块公开出口，不在文档调整中批量移动文件。

路由覆盖 `/`、`/opportunities`、`/favorites`、`/projects/:id`、`/tasks/:id`、`/publish`、`/publisher` 和占位的 `/my-interests`。页面按路由懒加载。

## 从旧 B 端文档采用什么

参考来源：旧 B 端项目 `docs` 下的前端架构、编码、样式、接口状态、测试和 Skill 文档。它们提供工程方法，不替代 C 端产品定义。

| 原有方法 | C 端处理 |
| --- | --- |
| 按业务模块组织、公共层单向依赖 | 采用，按当前目录落实 |
| 服务端状态与草稿分离 | 采用 Vue Query 与本机草稿，HTTP 接入时继续使用 |
| React Hooks、Ant Design 组件约定 | 转换为 Vue Composition API 和 Element Plus 约定 |
| 设计变量、组件样式边界 | 采用，已有全局样式债务逐步收敛 |
| 按风险验证、避免重复全量回归 | 采用，见测试规范 |
| B 端需求树、甘特图、AI 任务及权限体系 | 不直接引入，按 C 端实际需求另行设计 |

## 当前与目标的差距

当前部分服务方法同步读取本机数据，写操作使用手动异步处理和缓存失效；尚未统一为 HTTP 异步查询和 useMutation。全局样式也存在标签选择器和组件内部覆盖。规范约束新增代码，旧实现随相关改动逐步整理，不能宣称这些问题已经解决。

Web 页面先完成产品验证，再接共享 Java 后端。可复用业务模型、接口映射和无平台规则；未来小程序 / App 的 UI 与平台能力单独评估，不承诺 DOM / CSS 或 TypeScript 能直接复制到 uni-app x。
