# 测试规范

## 按风险选择检查

| 变更 | 必要验证 |
| --- | --- |
| 文档、说明文字 | 内容准确性、相对链接与命令核对 |
| 单页面低影响样式 | 目标页面、受影响视口、相关交互；无新风险不跑全量检查 |
| 单模块逻辑 | 类型检查、lint、受影响业务测试和目标流程 |
| 公共组件、全局样式、跨模块状态 / 契约、存储、构建配置 | npm run check，加受影响浏览器流程；共享布局覆盖桌面与移动端 |
| 真实接口接入 | 在上一项基础上验证浏览器 → API → 后端数据 → 响应的完整链路 |

同一版本检查通过后，不因总结或交付再次重复执行；只有新改动、失败或未解决风险才扩大验证。不要为可逆、低影响改动添加镜像实现的测试。

## 命令与覆盖范围

- `npm run typecheck`：Vue / TypeScript 类型检查。
- `npm run lint`：静态规则。
- `npm run test -- src/services/mock/mock.test.ts`：针对当前模拟业务测试文件。
- `npm run check`：类型、lint、测试和构建完整检查。

现有 6 项业务测试覆盖筛选、数据升级、收藏、申请边界、权限、容量和发布关联，部分断言在同一测试中。它们不是实际认证、数据库并发或全站端到端测试。当前没有可直接调用的 e2e npm 脚本。

## 浏览器验证

优先验证本次改动影响的流程，等待目标元素或请求状态，不用固定长时间 sleep 代替判断。涉及登录、收藏、发布和选择承接者时检查加载、失败、重复操作与状态变化；响应式改动检查对应尺寸的溢出、遮挡及可点击性。

保留实际验证的版本、日期、视口、路径、结果与限制；历史截图不充当当前页面证据。网络样例视频不能据此保证线上播放质量。

复用用户已启动的服务，不擅自重启。确需自行启动且任务允许时记录进程归属，完成后仅清理自己启动的进程。用户要求手动管理服务时保持停止状态，不为文档检查启动服务。

## 页面重构的迭代节奏（2026-11-09）

开始修改时说明验证等级。用户要求先看效果、粗版或连续视觉试调时，采用快速迭代：验证当前页面、目标视口与目标交互，不默认在每轮运行完整检查、构建或双端截图。结构确认后统一做类型、lint 和目标流程检查；定稿、提交或部署前做完整检查及受影响桌面和移动流程。

快速迭代不豁免接口协议、权限、安全、真实写入、删除、持久化和构建配置的风险验证。共享改动仍按上方风险表执行；发现失败先区分产品缺陷、测试定位问题和环境问题，再补直接相关检查。

测试查询优先使用可见文本、角色和标签；只在缺少合理语义定位时使用测试 ID。测试须清理 mock、timer、DOM 和 QueryClient，不靠 skip、提高全局超时或固定长等待掩盖失败。真实写入验证使用带标识的临时数据并清理，一条路径完成操作、保存、刷新回显，不为相同结论重复手工写入。
