# 编码规范

## Vue 与类型

新增业务使用 Vue 3 Composition API、`<script setup lang="ts">`。对外 props、事件、服务输入输出定义明确类型；外部未知数据先使用 unknown 并校验，不用 any 绕过问题。

派生值优先 computed；watch 用于副作用，不维护可从现有状态推导的重复状态。监听器、定时器和订阅需要清理。列表使用稳定业务 ID，不以数组索引替代业务身份。

## 职责与复用

页面负责组合布局、查询状态和用户操作。网络协议、业务约束和数据适配进入 services / domain，不能散落在页面中。出现重复业务流程时抽 composable；纯展示复用进入 shared/ui，带业务规则的组件保留在所属模块。

文件过长或同时承担多种职责时评估拆分，以可理解性为准，不为行数机械拆文件。跨模块复用尽量使用公开入口，不深度导入其他模块的内部实现。已有跨模块引用随相关工作整理。

## 状态与交互

异步操作处理 loading、错误、空态和重复提交。成功后按影响范围更新或失效查询，不无条件刷新整页。表单草稿不得直接修改查询缓存对象。服务端错误用用户能理解的文本呈现，同时保留开发定位信息，避免暴露秘密。

不要凭猜测加入性能缓存或复杂抽象；先定位实际瓶颈。高频输入与大块展示有独立更新需求时再拆分。

## 依赖与提交

依赖固定版本并同步 package-lock.json，安装已有锁定依赖使用 npm ci。新增依赖说明用途，避免为简单能力引入整套框架。不得提交 token、密码、私钥和真实个人资料。

变更说明区分已实现、模拟行为和未来计划；检查范围遵循[测试规范](测试规范.md)。
