# 编码规范

## Vue 与类型

新增业务使用 Vue 3 Composition API、`<script setup lang="ts">`。对外 props、事件、服务输入输出定义明确类型；外部未知数据先使用 unknown 并校验，不用 any 绕过问题。

派生值优先 computed；watch 用于副作用，不维护可从现有状态推导的重复状态。监听器、定时器和订阅需要清理。列表使用稳定业务 ID，不以数组索引替代业务身份。

## 职责与复用

页面负责组合布局、查询状态和用户操作。网络协议、业务约束和数据适配进入 services / domain，不能散落在页面中。出现重复业务流程时抽 composable；纯展示复用进入 shared/ui，带业务规则的组件保留在所属模块。

文件过长或同时承担多种职责时评估拆分，以可理解性为准，不为行数机械拆文件。跨模块复用尽量使用公开入口，不深度导入其他模块的内部实现。已有跨模块引用随相关工作整理。

## 状态与交互

异步操作处理 loading、错误、空态和重复提交。成功后按影响范围更新或失效查询，不无条件刷新整页。表单草稿不得直接修改查询缓存对象。服务端错误用用户能理解的文本呈现，同时保留开发定位信息，避免暴露秘密。

不要凭猜测加入性能缓存或复杂抽象；先定位实际瓶颈。高频输入与大块展示有独立更新需求时再拆分。

## 依赖与提交

依赖固定版本并同步 package-lock.json，安装已有锁定依赖使用 npm ci。新增依赖说明用途，避免为简单能力引入整套框架。不得提交 token、密码、私钥和真实个人资料。

变更说明区分已实现、模拟行为和未来计划；检查范围遵循[测试规范](测试规范.md)。

## 重构时的统一约定（2026-11-09）

本文件是 C 端编码约定入口；架构、接口、样式和验证各自维护在现有对应文档，避免复制出多份权威规范。借鉴来源和适配边界见[规范借鉴与重构基线](规范借鉴与重构基线.md)。

- 页面与组件文件使用 PascalCase，composable 使用 `useXxx.ts`；函数和变量用 camelCase，真正固定的常量用 UPPER_SNAKE_CASE。协议字段保持后端原名，不为命名统一修改外部契约。
- 业务状态使用联合类型、映射或领域函数，避免在组件各处散落字符串判断。展示模型与 HTTP DTO 在服务边界显式转换。
- 具名 props 和事件类型表达业务意图；复杂 composable 管理完整的请求、订阅、定时器生命周期，防止旧请求完成后覆盖新路由或新编辑会话。
- 输入值在最小必要组件内即时更新；搜索提交或防抖与输入回显分离。编辑草稿独立于查询缓存，不让每次按键触发整页列表更新或请求。
- 昂贵区域按需要用条件渲染和职责拆分；仅用 CSS 隐藏不会停止组件逻辑。优化前确认实际开销，不套用 React 的 memo/useCallback。
- 注释说明业务原因、边界和兼容限制，不逐行翻译实现；TODO 说明待办事项和处理条件。
- 沿用所在文件格式（当前源码以双引号、分号为主）、UTF-8 与 LF。暂不引入 B 端单引号格式或全仓格式化；依赖版本以本项目 package.json 和 lockfile 为准。

## 业务方法注释

业务服务、composable及承担业务规则的函数应说明用途、数据归属和关键边界。涉及正式内容与草稿、权限、版本、幂等或异步状态变化时，写明实际行为和失败条件；关键私有业务函数同样适用。复杂对外函数使用 JSDoc，普通转发和明显访问器不机械补模板。修改逻辑时同步更新注释，避免将演示行为描述为真实保存或授权。后端采用中文 Javadoc，具体见后端 docs/coding-standards.md。
